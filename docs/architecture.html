System Architecture

Factory Inventory Management System

A full-stack demo application for inventory tracking, order management, demand forecasting, and spending analytics across factory warehouses. Vue 3 single-page app, Python FastAPI service, and in-memory mock data loaded from JSON — no database.

Vue 3.4 · Composition API Vite 5 Vue Router 4 Axios FastAPI 0.110+ Pydantic 2 Uvicorn Python 3.11+ · uv pytest

Data Flow — the filter round-trip

Four global filters (Time Period, Location/Warehouse, Category, Order Status) live in a single shared composable and drive nearly every view. A change to any filter re-fetches data from the API.

  1. User changes a filter FilterBar.vue <select> updates a ref in useFilters.js (singleton state shared across all components).
  2. Views react Each view has watch([selectedPeriod, selectedLocation, selectedCategory, selectedStatus], loadData).
  3. Filters serialized getCurrentFilters() returns { warehouse, category, status, month }; 'all' values are dropped.
  4. API call api.js builds a query string and issues axios.get() to http://localhost:8001/api/…
  5. Server-side filtering FastAPI handler runs apply_filters() (warehouse / category / status, case-insensitive) then filter_by_month() (direct 2025-01 match or Q1-2025 quarter expansion) over in-memory lists.
  6. Validation Result is coerced through the endpoint's response_model (Pydantic) before serialization.
  7. Render Raw rows land in refs (allOrders, inventoryItems…); computed properties derive KPIs, chart series, and tables. SVG charts are pure functions of that computed data.

Note: /api/inventory has no time dimension, so it ignores the month filter. Some derived views (e.g. dashboard category chart, backlog) further narrow results client-side by cross-referencing SKUs.

Key Patterns & Conventions

Reactivity

  • Raw API data in ref(); everything derived in computed()
  • Filter state is a module-level singleton in useFilters.js — imported, not provided/injected
  • v-for keys use stable IDs (sku, month), never array index
  • Dates validated (isNaN(date.getTime())) before .getMonth()

Backend

  • Filters applied sequentially on list copies — originals never mutated
  • 'all' / empty filter values are treated as "no filter"
  • Category & status matched case-insensitively
  • Every list endpoint declares a response_model
  • Update Pydantic models whenever JSON shape changes

Design system

  • Slate/gray palette — #0f172a, #64748b, #e2e8f0
  • Status colors — green (delivered/ok), blue (shipped/info), yellow (processing/warn), red (backordered/error)
  • Charts are custom inline SVG; layouts use CSS Grid; no emojis in UI
  • Revenue goals: $800K / month single, $9.6M YTD across all months

Demo Constraints

This is a workshop demo, not production software. No database (data resets on server restart) · no authentication (mock user in useAuth) · CORS allows all origins · no rate limiting or input sanitization · API base URL is hardcoded to localhost:8001. The frontend also calls a few endpoints (tasks, purchase-order creation) that the current backend does not implement — those paths are stubbed for future workshop exercises.

Running Locally

Backend

cd server && uv run python main.py
→ http://localhost:8001 · docs at /docs

Frontend

cd client && npm install && npm run dev
→ http://localhost:3000

One-command (macOS/Linux): ./scripts/start.sh · stop with ./scripts/stop.sh.
